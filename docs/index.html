How It Works

One orchestrator. Infinite flexibility.

AppVelocity replaces rigid, fixed pipelines with a true AI reasoning loop. The orchestrator LLM thinks, acts, observes the result, and decides what to do next, adapting as it goes.

1
Reason
Each iteration, the orchestrator LLM reads a compact snapshot of the current project state (what has been done, what failed, what is left) and decides which capability to invoke next. No predetermined sequence.
2
Act
The orchestrator calls one of AppVelocity's specialized tools — fetch design data, generate code, validate output, repair errors. Each tool does one thing extremely well and returns a concise result.
3
Observe & Adapt
The tool result is fed back to the orchestrator as an observation. It adapts by re-generating a failing screen, running a targeted repair, or taking an entirely different path to reach a working, compilable project.
Under the Hood

ReAct Agent Loop

The core of AppVelocity is a ReAct (Reason + Act) while-loop. The orchestrator runs up to 30 iterations. It has access to 12 specialized tools. Full file content never touches the LLM. Only compact summaries flow through the context window, keeping every iteration fast and cost-efficient.

30 max iterations 12 specialized tools Self-healing output
// agent-loop.ts
for i = 1..30:
  prompt = buildPrompt(memory)
  call = llm.chat(prompt, tools)
  result = dispatch(call)
  memory.observe(result)
  if zipBuffer: break
return output

Live Capability

Design → Code, Fully Automated

The first capability in AppVelocity is design-to-code generation: converting a Figma file into a structured React Native or Flutter project, automatically.

🔗
One Input. Complete Project.
Paste a Figma URL and select your framework. AppVelocity reads every layer, extracts design tokens, plans the navigation structure, generates all screens and shared components, assembles the project scaffold, validates the output, and delivers a downloadable ZIP ready to open.
🧠
LLM Orchestration, Not a Script
The orchestrator LLM dynamically decides the generation sequence every iteration. If Gate 1 syntax validation fails on a screen, the agent calls repair_file immediately, not after everything else finishes. Self-healing is built into every run.
🎯
Design-System Fidelity
Colors, typography, spacing, corner radii, and component variants are extracted directly from Figma variables and written as typed named constants in a theme file, not hardcoded values. Your design system is the source of truth.
✅
Multi-Gate Quality Assurance
Five quality gates run automatically: Babel AST parse (Gate 1), IR structural validation (Gate 2), workspace tsc / dart analyze (Gate 3), LLM repair loop (Gate 5), and full compilation check with one auto-fix pass (Gate 6). Quality is checked at multiple stages before the ZIP is created.
📦
Two Frameworks. One Tool.
React Native (TypeScript + Zustand / Redux / Jotai) and Flutter (Dart + Riverpod / BLoC / Provider) are fully supported today. Native Android and iOS targets are on the roadmap. The platform-neutral Design IR makes new targets a plugin addition.

Tool Registry

12 Specialized Tools. One Orchestrator.

Every tool is a thin, focused wrapper around battle-tested logic. The orchestrator LLM picks which ones to call, in what order, based on what it observes, not a predetermined sequence.

📥
Fetch Figma
fetch_figma
Retrieves the complete Figma document tree and design variable definitions via the Figma REST API. Always the first tool called.
👁️
Vision Analysis
analyze_design
Exports screens as PNG images and runs a Worker LLM vision pass to detect spacing systems, icon families, image assets, and font usage. Non-fatal.
🔀
Build IR
build_ir
Transforms raw Figma JSON into a platform-neutral Design IR covering all screens, components, flex rules, design tokens, and accessibility metadata.
🧭
Plan Generation
plan_generation
Analyses the IR and produces a structured execution plan: project name, entry screen, screen list, navigation graph, and component dependency order.
⚙️
Generate All
generate_all_components
Runs parallel code generation across all screens and components in the execution plan. Auto-runs Gate 1 and Gate 3 checks after generation.
🔧
Generate One
generate_component
Generates or regenerates a single named screen or component. Used by the orchestrator when one file needs to be rebuilt without rerunning everything.
✅
Validate File
validate_file
Gate 1: runs Babel AST parsing and structural checks on a specific generated file. Returns pass/fail with line-level error attribution.
🩹
Repair File
repair_file
Gate 5: sends a failing file alongside its specific errors to a Worker LLM for a targeted, contextual fix rather than generic reformatting. Always saves the best version.
🔍
Workspace Check
run_workspace_check
Gate 3: writes all generated files to a temp workspace and runs tsc --noResolve or dart analyze. Returns errors grouped by file for targeted repair.
🏗️
Assemble Project
assemble_project
Generates the full project scaffold (entry point, router, state management setup, package.json / pubspec.yaml) and merges it with all generated screens.
🏁
Compile Check
run_compilation_check
Runs the full compiler (npx tsc --noEmit or flutter analyze) on the assembled project in a temp directory. Automatically applies one LLM fix pass on failure.
📦
Create ZIP
create_zip
Packages the complete project into a downloadable ZIP archive and signals the orchestrator to stop. Called after compilation passes or after the max-retry limit.
Technology

Built on the best AI stack

AppVelocity uses the right model for each job: a powerful orchestrator for dynamic reasoning, specialized models for code generation, and deterministic tools for validation.

🧠
GPT-4o
Orchestrator LLM
Drives the ReAct loop. Reads the current project state summary, reasons about what tool to invoke next, and adapts its strategy based on tool observations. Sees only compact summaries, never raw file content.
✦
Claude Sonnet
Code Generation · React Native
Primary Worker LLM for generating TypeScript and React Native code. Produces strict TypeScript, StyleSheet.create patterns, and framework-idiomatic component structures from the Design IR.
◆
Gemini 2.0 Flash
Code Generation · Flutter
Worker LLM for Flutter/Dart generation and refinement. Enforces const constructors, null safety, named parameters, and proper widget lifecycle patterns automatically across every generated Dart file.
🎨
Figma REST API
Design Data Source
Official Figma API for complete document tree retrieval, design variable extraction, and PNG screen export. Includes rate limiting, exponential backoff, and a 5-minute LRU cache for reliability.
⚡
Next.js + SSE
Web Platform
The agent runs asynchronously on the server. Real-time progress streams to the browser via Server-Sent Events as each tool call happens. No polling. No page refreshes.
🔬
Babel AST + tsc + dart
Deterministic Validation
Quality gates use real compilers and parsers, not heuristics. Babel parses TypeScript for syntax errors. tsc validates type correctness. dart analyze and flutter analyze enforce Dart compilation correctness.
